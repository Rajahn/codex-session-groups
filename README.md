# Codex Session Groups

给 Codex 桌面端的工作目录增加一层**纯视觉会话分组**。分组只帮助人整理侧边栏，不会改变会话、工作目录、上下文、Goal、分支或 worktree。

## 交互

- 右键项目文件夹，或点击项目右侧的 `…`，在原生“项目操作”菜单中选择“新建分组”。
- 点击分组行展开/收缩；也支持 `Enter`、空格、左右方向键。
- 双击分组名、按 `F2`，或打开分组右侧的 `…`，可随时重命名。
- 将鼠标移到会话行上，从左侧六点拖拽柄拖到分组，即可移入。
- 拖到同项目的项目文件夹、列表空白处或未分组会话，即可移出。
- 分组只投影 Codex 当前在项目列表中实际渲染的会话：当前能显示 1 条就计数 `1`，不会显示 `1/3`，也不会因为保存过但当前缺行的会话阻塞展开、收缩或排序。
- 注入层不会自动点击 Codex 原生“展开显示”。较老会话是否加载完全由用户和 Codex 原生界面控制；它出现后若仍保留同一个任务 ID 的视觉归属，会自然回到对应分组。
- 通过 Codex 原生按钮归档会话后，该会话会从视觉分组移出；以后恢复归档时回到项目的未分组区。
- 新建会话在同一侧边栏行内从临时 ID 升级为正式 ID 时，会沿用该行已有的项目、分组和完整指纹，不受原生分页是否加载完整影响。跨重启只能靠指纹恢复时，仍要求完整列表和严格一对一；同名候选不唯一时不会自动猜测，已观察到的歧义也不会因为候选减少或重启而失效。
- 删除分组只会删除视觉归类，所有 Codex 会话仍然保留。

分组会优先显示，未分组会话保留在后面。较老会话仍由 Codex 原生的“展开显示”控制；注入层不会替用户展开分页。

## 启动

要求 macOS、Codex/ChatGPT 桌面端和 Node.js 22+。没有 npm 运行时依赖。

1. 完全退出当前 Codex。
2. 在本目录执行：

   ```bash
   npm start
   ```

3. 保持这个终端进程运行。它会启动 Codex，并在新 renderer 出现时重新注入。

当前实现只有通过上述启动器启动时才会显示分组。直接从 Dock 或 Spotlight 启动 Codex 时，分组 UI 不会注入，但数据不会因此丢失；退出后重新通过启动器打开即可恢复。

也可以双击 [Start Codex with Groups.command](./Start%20Codex%20with%20Groups.command)。如果 Codex 已经运行，启动器会安全退出并提示先关闭，不会强制终止现有窗口。

开发调试时，可连接已经启用 CDP 的隔离实例：

```bash
npm run attach -- --port 9337 --once
```

## 数据与安全边界

- 分组状态只保存在 Codex renderer 的 `localStorage` 键 `codex-session-groups:v1`。为识别新建会话重启后的正式 ID，会随分组映射保存标题、host 和 kind 三个最小指纹，以及不含正文的歧义阻断标记。
- 同一 Codex 用户配置下，正常退出、重启和应用升级不会主动清除这个键；清除 Codex 用户数据或改用另一个用户目录则不会带上分组。
- 不读取或修改 `~/.codex/.codex-global-state.json`。
- 不修改 `/Applications/ChatGPT.app`，不替换应用包，也不影响应用签名。
- 不访问网络，不启动服务，不保存会话正文，不向会话注入上下文。
- 只通过 Codex 提供的语义化 DOM 标记定位项目和会话；标记缺失时停止渲染。
- 不调用 Codex 的归档、恢复或删除能力。只有用户显式点击原生“归档聊天”且对应行确实消失后，才删除该会话的一条视觉分组映射；不会仅凭列表暂时缺少某行做清理。
- 同一 DOM 行若仍保留注入层写入的旧临时 ID、项目、分组和完全一致的标题/host/kind，可直接迁移到该行的新正式 ID；正式 ID 已分组或任一字段不一致时立即停止。除此以外的指纹迁移只在项目已“展开全部”、旧 ID 明确为 `client-new-thread`、并且完整 source-target 匹配图严格一对一时发生；已分组候选、置顶区同名行和弱指纹重叠都会作为歧义阻断项。列表不完整、缺少旧指纹或存在任一歧义时保持原映射不动；已经观察到的歧义会按临时 ID 持久化，避免重启后错误迁移。
- 已保存但当前没有原生行的成员不参与计数、折叠和排序，也不会触发自动分页；其视觉映射静默保留，避免把暂未渲染误判成归档或删除。已受管的原生行即使临时丢失 thread ID，也会清除旧隐藏和排序标记。
- 原生会话节点不会被移动或克隆，只通过 CSS `order` 做视觉排序，因此点击、置顶、归档和原生重命名仍由 Codex 处理。

启动器把调试端口绑定到 `127.0.0.1`，默认使用随机端口，并只接受同一端口上的 loopback WebSocket 与 Codex 主 renderer。注入结果必须回读到精确版本；renderer 切换或本地调试端点短暂不可用时会重试。CDP 仍是本机调试能力，退出 Codex 后端口随之关闭。

## 已知边界

- 这是非官方前端注入。Codex 更新后若语义化 DOM 标记变化，可能需要适配。
- 置顶会话继续留在 Codex 原生“置顶”区，不计入项目内分组的当前可见数。取消置顶后，任务只有在 Codex 重新把它渲染进项目列表时才重新显示在分组中；既有分组归属不会仅因暂时缺行而删除。
- 分组只在当前本机配置中保存，不跨设备同步。
- 如果两个新建会话的标题、host 和 kind 完全相同，重启后的自动迁移会停止，需要人工重新归类。
- 本项目有意不包含任务面板、共享上下文、数据库、AI、自动认领、定时执行或云同步。

## 验证

```bash
npm run check
```

自动化验证包含模型测试、启动器重试测试和 Happy DOM 交互测试：当前可见成员投影、缺行不阻塞交互且不自动点击原生分页、同一行在不完整列表中的精确 ID 迁移、列表重挂载后的即时重投影、受管行丢失 thread ID 后恢复、归档等待期间 ID 迁移、跨 renderer 持久化歧义阻断、置顶同名阻断，以及新版本安全接管旧 renderer。Happy DOM 仅为开发测试依赖，运行时依赖仍为零。
